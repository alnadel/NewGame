This is the binding input for the three v1.1 build batches. **Precedence:** §0 Director's amendments override everything below them, then the batch items (§2-§4), then the contracts (§1), then docs/V1_1_PLAN.md. ## 0. Director's amendments (BINDING; they override the items and contracts below)

These amendments come from the pre-build critique and the owner's "compact" brief. Each one names the batches it binds. Where an amendment changes a contract, every batch implements the amended version.

### A1. World identity: legacy links and old Dailies never change world [core, gameRender, uiMeta]

**RunConfig and planOn**
- `RunConfig` gains `plan?: boolean`. It is part of world identity.
- `World.planOn = cfg.forecast !== undefined || (cfg.plan ?? (profile === 3 && !tutorial))`.
- core exports `PLAN_START_DATE = '2026-10-14'`.

**Daily runs**
- The session sets `plan: date >= PLAN_START_DATE`. ISO strings compare lexicographically.

**Challenge codes (amends CC-8)**
- An `'e'` code has a new key `pl` (0 or 1), placed after `nc`.
- v1.1 encoders always write `p`, `dr`, `nc` and `pl`.
- If `p` is absent, the code is legacy. It decodes to `{p: 3, dr: 55, nc: 0, pl: 0}`, which reproduces the v1.0 world exactly.
- If `pl` is absent but `p` is present, treat it as `pl = 1` when `p === 3`, else 0.
- The session passes `plan: pl === 1`.

**Debug runs**
- New URL parameter `?plan=0|1`, which forces `cfg.plan`. It marks the run as debug.
- Every gameRender screenshot, perf and pixel baseline pins `?plan=0` so it stays comparable across batches.

This amends CC-2.

**Rungs**

### A5. Lesson pass rule [core, gameRender]

This amends CO4 and CC-5.

**Pass rule**
1. Wait for the first lit tick with `s.ready === 0`.
2. From then on, record θ each time Nubs becomes lit.
3. θ must then move ≥ 15° from that value, whatever the input source (drag, keys or wheel).
4. Nubs must then stay in full shade (f = 0) for 15 consecutive ticks.
5. Emit `lessonDone`.

There is no per-downEdge reset, and a passing shadow alone can never satisfy the rule.

**Time scale**
- The lesson's 0.5× time scale starts with the first lesson hint, as in v1.0.
- It ends when `lessonOn` becomes false.
